# 全局技能集 (Global Skills)

本仓库包含一组生产级技能（skills），用于扩展 AI 代理的能力边界。每个 skill 封装特定领域的专家经验、最佳实践与检查清单，便于在对话或自动化流程中被发现与调度。本文件为技能索引与最小描述（MVP），便于快速查找与后续完善。

---

## 变更说明

- **目标**：按统一的前缀分类规范重组 skills 目录结构，提高可维护性与可发现性。
- **范围**：仅修改文档索引结构与目录名称，不涉及 skill 代码逻辑。
- **分类规范**：使用 8 个一级分类前缀（`lang-`, `build-`, `design-`, `ai-`, `dev-`, `content-`, `research-`, `memo-`, `meta-`, `tool-`）。
- **回滚**：已保留原文件备份 `README.md.bak`（如需还原，请复原该备份文件）。
- **验证**：人工打开本文件核对条目是否齐全；可通过版本控制查看变更差异。

## 目录（按分类前缀组织）

### 编程语言 (lang-\*)

用于特
定编程语言的工程实践、类型设计与性能优化。

- **lang-js**: JavaScript 工程实战、兼容性与性能优化要点。
- **lang-py**: 面向 Python (3.11+) 的类型化、异步与架构建议。
- **lang-ts**: 现代 TypeScript 开发实践、类型设计与工程化建议。
- **lang-rust**: Rust 系统级编程与性能/安全实践。

### 构建与框架 (build-\*)

用于应用/框架开发、项目脚手架与工作流自动化。

- **build-app-step01**: 应用构建初期的引导步骤（项目初始化、依赖、骨架）。
- **build-app-workflow**: 从开发到发布的工作流模板（CI/CD、测试策略、发布步骤）。
- **build-executing**: 将已批准计划系统化执行的流程与监控机制。
- **build-mcp**: 多组件项目脚手架与自动化构建流程模板。
- **build-tauri**: 使用 Tauri 构建跨平台桌面应用的实践要点。
- **build-vue**: Vue 3 / Nuxt 3 前端工程与状态管理实务。

### 设计系统 (design-\*)

用于 UI/UX、视觉设计、品牌规范与设计系统建设。

- **design-arch**: 系统架构设计、模式评审与 ADR（决策记录）模板。
- **design-brand**: 企业品牌一致性检查与视觉识别 (VI) 实施要点。
- **design-canvas**: 可用于海报、插画与视觉排版的设计流程与资源建议。
- **design-frontend**: 面向生产级 UI/UX 的设计系统与可实现规范。
- **design-theme**: 生成与管理视觉主题（文档/界面）的模式与样式库。

### AI 与大模型 (ai-\*)

用于 AI 模型微调、提示工程、视觉生成等相关能力。

- **ai-finetune**: LLM 微调流程、数据标注标准与评估方法。
- **ai-imagen**: 基于 Imagen 模型的视觉原型、图标与素材生成参考。
- **ai-prompt**: 提示词设计、分步推理与提示链（chain-of-thought）构建策略。

### 开发工具与工程 (dev-\*)

用于代码审查、文档化、运维、游戏开发等工程实践。

- **dev-devops**: 系统运维、基础设施管理与持续部署最佳实践。
- **dev-documenter**: 自动与手工相结合的代码文档生成与维护策略。
- **dev-game**: 游戏引擎相关逻辑、性能优化与调试实践。
- **dev-reviewer**: 代码审计流程、常见风险检查项与修复建议模板。

### 内容创作 (content-\*)

用于内容生产、多渠道格式化与计划编写。

- **content-creator**: 内容生产流水线与多渠道格式化的最佳实践集合。
- **content-plans**: 编写技术规格与实施计划的模板与检查项，支持分阶段交付与验收。

### 研究与调查 (research-\*)

用于深度研究、市场分析、竞争情报与文献汇总。

- **research-deep**: 深度研究与情报收集代理，包含市场/竞争/文献汇总方法。

### 记忆与上下文 (memo-\*)

用于上下文管理、信息存储、RAG（检索增强生成）工程。

- **memo-beads
  **: 记忆珠链模式，用于结构化存储关键信息点与引用。
- **memo-kontext**: 上下文管理、检索增强生成（RAG）与文档片段工程实践。
- **memo-memo0**: 基础备忘录与知识积累系统框架。

### 元技能系统 (meta-\*)

用于技能发现、创建、调度与代理驱动开发的元层能力。

- **meta-brainstorm**: 系统化需求分析与创意发散，用于在执行前明确目标与约束。
- **meta-creator**: 用于快速创建/扩展 skill 架构与元数据的工具/模板说明。
- **meta-subagent**: 使用独立子代理并行拆分任务、协调交付的实践与模式。
- **meta-superpowers**: 技能发现与调度的枢纽；在对话开始时选择与加载合适的技能与工作流。

### 工具与第三方服务 (tool-\*)

用于特定工具集成、第三方平台适配与辅助功能。

- **tool-elementor**: Elementor 页面编辑器集成与内容管理实践。
- **tool-hello**: 会话启动与技能加载状态的标准化声明。
- **tool-xiaohongshu**: 针对小红书等社交平台的内容/人才筛选与策略支持（行业专用）。

## 使用与维护建议

- 每个 skill 目录应包含一个 README，说明用途、输入/输出、调用方式与检查表（若尚未添加，请逐步补充）。
- 文档更新须与实际能力同步：新增/修改 skill 时同时更新此索引、skill 内 README 与调用示例。
- 禁止在代码或文档中硬编码密钥/令牌；示例中使用占位符并在 README 中标注安全注意事项。
